# Architecture

The React client calibrates an empty-guide baseline from downscaled webcam frames, measures the camera's idle noise, and then detects card entry as a sustained difference from that baseline. Stability uses an adaptive threshold derived from observed noise. A stable card is captured once, and another capture is prohibited until the guide returns to its baseline. This keeps camera latency out of the server and prevents repeated scans of a stationary card.

FastAPI accepts the capture and runs recognition off the request thread. The recognizer rectifies the largest card-shaped quadrilateral, falling back to the browser's known center guide for low-contrast sleeves. CPU-optimized PP-OCRv4 mobile models extract the name, collector/total pair, modern printed set/language code, and copyright year. The title parser rejects short mana-cost noise, while legacy footer OCR uses conservative digit-confusion ranking. A perceptual artwork hash supplies independent evidence, and Box Mode restricts both Scryfall and local artwork candidates to its selected set. Stage timings are logged for preprocessing, OCR, metadata lookup, artwork matching, and ranking so performance regressions are visible.

Default automatic mode writes inventory only at 98.5% or higher. Lower results retain the normalized camera image as a pending review and immediately release the capture request so bulk scanning continues. A non-blocking receipt reports either outcome. When automatic mode is disabled, 70%+ candidates instead use a keyboard-first dialog; the capture promise stays open until Enter or Backspace. Accepting a correction performs the atomic inventory upsert and stores its visual hash as a local printing reference, then removes the no-longer-needed scan file.

Reference indexing is explicitly set-scoped. `/api/references/sync/{set_code}` starts a throttled background download from Scryfall, computes 64-bit pHashes, and stores only metadata plus hashes in PostgreSQL. It is resumable because existing Scryfall IDs are skipped. This makes a booster-box workflow fast without imposing an enormous all-printings bootstrap.

PostgreSQL is the production database. SQLite is supported for tests and simple development. Inventory uniqueness is based on printing, finish, language, condition, collection, and storage location. Providers implement small metadata and pricing interfaces so Scryfall can later be joined by commercial sources. Camera thresholds are client-side and tunable live; brightness, contrast, and motion telemetry make calibration observable rather than guesswork.

Deck entries allocate quantities from inventory rows rather than copying card metadata. Every mutation compares total allocation across all decks with the owned row quantity, and PostgreSQL row locking protects bulk additions from over-allocation. Fully assigned rows disappear from Deck Builder availability; removing a deck or entry releases its physical copies. Scan defaults may include a deck ID so the single copy created by an accepted scan is allocated immediately. The legacy collection/status fields remain internal compatibility dimensions; current organization uses decks plus editable physical storage labels.

The production web container uses same-origin requests and proxies `/api` to the API service. This avoids browser-host `localhost` assumptions and makes the same Compose file usable on a workstation or Unraid/LAN host. Backend tests launch isolated temporary Uvicorn servers and databases, exercising actual HTTP and application lifespan behavior rather than an in-process mock transport.
